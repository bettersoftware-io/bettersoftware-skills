# Baseline run, 2026-10-04

What an agent builds when nobody tells it the rules, and what the kit then
says about the result.

## Setup

- Claude Code, model Claude Fable 5.1, in an empty folder with no instruction
  file. The user's usual plugins were installed; the superpowers
  test-driven-development skill loaded itself during task 3.
- Three prompts, given in order with the conversation cleared between them.
  Each named the stack and said nothing about architecture or how to test.
- One run per task. Treat every "correct" below as "correct once".

### The prompts

1. Build a small web app that shows a live-updating list of stock prices.
   Prices arrive over a WebSocket; include a small server that emits them.
   Stack: TypeScript, React, RxJS, Vite, in a pnpm workspace.
2. Add a second way to get prices: an in-browser simulator, so the app can run
   with no server. Which source is used is chosen at startup from an
   environment variable.
3. Two new behaviours: a price row flashes for 300 ms when its price changes,
   and a price that hasn't updated for 5 seconds is shown as stale. Implement
   both and add tests.

## What it built

Four packages (`apps/web`, `apps/server`, `packages/protocol`,
`packages/market`), about 650 lines of source and 390 of tests.

## Scores, by reading the code

### Correct without being told

| Rule | What the agent did |
|---|---|
| Inward package dependencies; apps never import each other | `protocol` ← `market` ← `server` / `web` |
| Wire types in one shared package | `packages/protocol` |
| `Observable` at the boundary, per-subscription state in a `defer` closure | Both price sources |
| Timed behaviour kept out of components | Flash and stale live in a pure reducer driven by a stream |
| Fake timers with exact boundaries | Advance by 299 ms, then by 1 |
| Simulator engine as shared production code | `packages/market`, used by the server and the browser |
| Snapshot on connect and on reconnect | `snapshot` then `ticks` |
| Leaf components are dumb | The row component renders props only |

### Partly

| Rule | What the agent did |
|---|---|
| Second source behind the same contract | Both return the same event stream, but the event type is declared in the WebSocket adapter's file and is the wire message plus `open`/`closed`. The simulator fakes transport messages to fit. |
| Config read at the edge | Parsing is separated and validated, but the environment is read in the root component |
| Enrichment in the core | Direction, flash and stale are in the reducer; delta, trend and sorting are computed in components |
| State as a fold | A pure reducer with time as an action, but no intents, and a cold stream: a second subscriber would open a second socket |

### Absent

| Rule | What the agent did |
|---|---|
| A domain package that owns entities and ports | None. The domain entity is the wire type. |
| A composition root | Wiring at module scope in the root component |
| No stream library in the UI | The root component imports RxJS operators |
| A bindings package | A hand-written subscribe-in-effect hook |
| A view-model seam | The root component cannot be rendered with fake data, and has no test |
| Contract tests across adapters | The simulator is tested alone; the WebSocket adapter has no test beyond its backoff function |
| UI tests through page objects | The row component is tested by a regular expression over rendered HTML |
| Fixture naming | `quote(...)`, a bare noun |
| Any enforcement | No lint, no dependency rules, no CI, no instruction file |
| Server as stream effects | An interval and event listeners |

## What the kit says about the same code

The code was copied unchanged. The only file added was an
`architecture.config.mjs` declaring `protocol` as shared, `web` as a client and
`server` as a server, with the kit's default layout.

```
FAIL structure (13)
FAIL dumb-ui (2)
SKIP port-contracts — no port interfaces were found, so there was nothing to check
FAIL dependencies (4)
19 finding(s).
```

Lint added six more: four `newspaper-order` and two `component-newspaper`.

### Absent rule, and whether a check caught it

| Absent rule | Caught by |
|---|---|
| A domain package that owns entities and ports | `structure`: no package has the role "domain" |
| A composition root | `structure`: the client has no `src/app`; `dumb-ui`: configuration read in a component |
| No stream library in the UI | `dumb-ui`, with file and line |
| A bindings package | `structure`: logic in the client outside its two folders (the hand-written hook is one of seven files named) |
| A view-model seam | `structure`, indirectly: no `src/ui`, components outside it |
| Contract tests across adapters | Not judged: with no ports the gate reports `SKIP`. `structure` reports the missing domain. |
| Any enforcement | Not applicable: the kit is the enforcement |
| UI tests through page objects | **Not caught.** No rule recognises a test that asserts on rendered markup directly. |
| Fixture naming | **Not caught.** The rule covers zero-parameter fixtures; this one takes arguments. |
| Server as stream effects | **Not caught.** Not checkable by a rule. |

The undeclared `packages/market` was also reported, and both apps importing it.

## What this decides

- Seven of the ten absent rules are caught deterministically. The three that
  are not go on the review checklist.
- The rules the agent followed unprompted are checked anyway. One run is not
  evidence about the next.
- The largest gap is the port: found, but declared in the wrong place and
  shaped by the wire format. No check sees that; it is a judgement call, and it
  is the first thing the review checklist and the port skill must cover.
